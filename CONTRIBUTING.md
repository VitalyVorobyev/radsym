# Contributing to radsym

Thanks for your interest in radsym. This guide covers the conventions the
codebase relies on. The authoritative architecture notes live in `CLAUDE.md`.

## Development commands

```sh
cargo fmt --all                                                       # format
cargo clippy --workspace --all-targets --all-features --exclude radsym-wasm -- -D warnings
cargo test --workspace --all-features                                # full tests
cargo test --workspace --no-default-features                         # minimal build
cargo bench                                                          # criterion benchmarks
cargo check -p radsym-wasm --target wasm32-unknown-unknown           # WASM crate
```

CI runs all of the above; please make sure they pass before opening a PR.

## Conventions

- **Coordinates:** `(x = col, y = row)` everywhere, matching
  `nalgebra::Point2<f32>`. x increases rightward, y downward.
- **Scalar precision:** `f32` for all pixel-level computation. No `f64` in the
  public API.
- **Error handling:** `thiserror`-based `RadSymError`; return `Result<T>`.
- **Determinism:** output ordering must be deterministic.
- **No allocations in hot loops** where avoidable.
- **Every public item needs rustdoc.** `cargo doc` runs with `-D warnings`.
- **Literature traceability:** algorithm implementations must cite their source
  paper (see the Algorithm Families table in `CLAUDE.md`).

## Dependency rules

- `core/` must not depend on the algorithm modules.
- `propose/`, `support/` depend only on `core/`.
- `refine/` depends on `core/` and `support/`.
- `affine/` depends on `core/` and `propose/`.
- `diagnostics/` may depend on all other modules.
- No OpenCV or heavy vision dependencies; `nalgebra` only for linear algebra.

## Testing

- Use the synthetic generators (circles, rings, ellipses) for new algorithm
  tests; assert quantitative thresholds (center error, IoU) where possible.
- Benchmark hot paths with criterion before optimizing.

## Versioning

The version is single-sourced from `[workspace.package] version` in the root
`Cargo.toml`. When bumping, update **only** the root `Cargo.toml` and
`CHANGELOG.md` — the member crates inherit it, and
`crates/radsym-py/pyproject.toml` reads it dynamically via maturin.

## Documentation & performance pages

- The mdBook lives in `book/`; build it with `mdbook build book`. To refresh the
  interactive WASM demo, run `./book/build.sh`.
- The published performance page is regenerated by a committed harness; see
  `docs/development/performance.md`.
